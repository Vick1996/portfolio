JobHub

A distributed job orchestration platform — scheduler, worker pool, notification service, and API gateway — built to be production-grade rather than a demo.

Problem

  • Most portfolio projects are CRUD demos that don't test distributed-systems judgment
  • Reliable job scheduling is deceptively hard: run multiple scheduler instances for high availability, and now two of them can fire the same job at once
  • Needed one scheduling model that handles both one-time and recurring (cron) jobs, not two systems bolted together

Approach

  • Split the system into scheduler, worker pool, notification service, and API gateway — each independently deployable
  • Scheduler runs as multiple replicas for HA, with Redis-based leader election so only one instance is ever the active trigger — same pattern Kubernetes uses, Redis instead of etcd
  • Idempotent trigger keys on top of leader election, so even a leadership handoff mid-trigger can't double-fire a job
  • Workers pull jobs via Kafka consumer groups rather than the scheduler pushing to specific workers — scales workers horizontally without the scheduler becoming a bottleneck
  • resilience4j circuit breakers around external calls, so one flaky dependency can't take down the pipeline
  • Next.js dashboard with TanStack Query for live job status
